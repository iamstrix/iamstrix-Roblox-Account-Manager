Plan: Low-graphics alt client + normal main client (RAM x Bloxstrap)

Executor: Codex. Planner notes are based on the repo at b7c7055 plus the uncommitted FastFlags work in the working tree (do not revert it — it is the base for this plan).

Goal
  • Accounts in "alt" groups launch on an extremely low-graphics Roblox client.
  • Only the main account launches on a normal-graphics client (the user's own Bloxstrap setup, untouched).
  • RAM and Bloxstrap cooperate: RAM detects Bloxstrap, reads its version/paths, never pollutes the user's Bloxstrap flags, and falls back to Bloxstrap's launch path whenever it must.

Architecture decision

Primary: dedicated alt client. RAM keeps its own client folder AltClient\<version-guid>\ (next to RAMSettings.ini). It is hard-linked from the matching Roblox/Bloxstrap version folder, so it costs almost no disk space. Only its ClientSettings\ folder is a real, separate directory, holding the low-graphics flags permanently. Alts are started by running AltClient\<guid>\RobloxPlayerBeta.exe directly. The main is always launched through Bloxstrap (protocol handler) with the user's own flags, and RAM never touches those flags.

This avoids swapping one shared ClientAppSettings.json back and forth, which is what causes races today: an alt launch and a main launch close together, Bloxstrap copying at the wrong moment, or a crash leaving alt flags on the main.

Fallback: the existing shared-client swap. This is the merge-on-top + backup/restore code already in ClientSettingsPatcher. RAM uses it for an alt launch when the dedicated client can't be prepared, for example when no installed version folder matches the live Roblox version. Launching through Bloxstrap also makes Bloxstrap update Roblox, so the next alt launch can use the dedicated client again.

In-game settings (GlobalBasicSettings) stay shared. RAM coordinates them with a launch gate and a saved "main snapshot" (Phase 4).

Phase 2: Bloxstrap integration

New file RBX Alt Manager/Classes/Bloxstrap.cs (static class Bloxstrap). It must work for Bloxstrap and for forks with a Modifications folder (Fishstrap, Voidstrap). Move the existing ClientSettingsPatcher.GetBootstrapperDirectory() here and keep a forwarding call so nothing breaks.

  • string Directory: the existing registry detection.
  • bool IsInstalled => Directory != null.
  • string ModificationsClientSettings => Path.Combine(Directory, "Modifications", "ClientSettings").
  • string GetVersionGuid(): read PlayerState.json → VersionGuid. Fall back to State.json → VersionGuid (older builds) and then State.json → Player.VersionGuid. Parse defensively with TryParseJson; return null on any failure.
  • string GetClientDirectory(): Versions\<guid> when it contains RobloxPlayerBeta.exe, else null.

Add ClientProfiles.FindClientSource(string wantedVersion). It returns the first folder named wantedVersion that contains RobloxPlayerBeta.exe, checking in this order:

  1. Bloxstrap\Versions
  2. %LocalAppData%\Roblox\Versions
  3. %ProgramFiles(x86)%\Roblox\Versions

wantedVersion is AccountManager.CurrentVersion, which AccountManager already fetches from clientsettings.roblox.com/v1/client-version/WindowsPlayer → clientVersionUpload. If CurrentVersion is still null (fetch not finished or failed), fall back to Bloxstrap.GetVersionGuid().

Acceptance: on this machine, Bloxstrap.GetVersionGuid() returns version-cec3ad5889b447cf and FindClientSource picks whichever installed folder matches the live version.

Phase 3: Dedicated low-graphics alt client

New file RBX Alt Manager/Classes/AltClient.cs (static class, all work done under a lock).

static bool TryPrepare(Account account, out string exePath, out string reason):

  1. Return false if setting UseAltClient is off, or the role isn't Alt.
  2. source = ClientProfiles.FindClientSource(...). If null, return false with reason "no installed client matches <version>". The caller falls back to the Bloxstrap launch, which updates Roblox.
  3. target = Path.Combine(Environment.CurrentDirectory, "AltClient", Path.GetFileName(source)).
  4. If target\.ram-source is missing or its content isn't source, (re)build the folder:
    • Walk source recursively. Skip the ClientSettings directory entirely. For every other file, call CreateHardLink(targetFile, sourceFile, IntPtr.Zero) (P/Invoke kernel32, CharSet.Unicode, SetLastError). If hard-linking fails (different volume, error 17), fall back to File.Copy and log it once.
    • Copy AppSettings.xml instead of linking it, so writes to either copy never reach the other.
    • Build into target + ".tmp" and rename it to target when done, so a half-built folder is never used. Write .ram-source last.
  5. Every time, write target\ClientSettings\ClientAppSettings.json from the account's group profile JSON:
    • Remove the _RobloxSettings key first.
    • Do not merge the user's Bloxstrap flags. The alt client gets only the alt profile.
    • Keep the existing UnlockFPS injection behavior consistent with ApplyProfile.
    • If two alts in different groups launch back to back, the lock plus the launch gate (Phase 4) keep them in order.
  6. Clean up stale clients: delete other AltClient\version-* folders when no running RobloxPlayerBeta process has its exe under them. Check with process.MainModule.FileName in try/catch, because the elevated second process throws. Deleting hard links never touches the source files.
  7. exePath = target\RobloxPlayerBeta.exe.

Also refresh the alt client from CreateLowGraphicsPreset (or just let the next launch rewrite it, since step 5 runs on every launch).

Phase 4: In-game settings coordination (GlobalBasicSettings_13.xml)

The flags force low render quality on alts (DFIntDebugFRMQualityLevelOverride, texture override) no matter what the shared XML says. The XML still controls FramerateCap and MasterVolume for alts, and the main's graphics. An alt that exits writes its low values back into the XML, and the main would read them on its next launch.

  • Launch gate: add static SemaphoreSlim LaunchGate = new SemaphoreSlim(1, 1) in ClientProfiles. JoinServer waits on it (await WaitAsync) before any settings write. It releases the gate when one of these happens first:
    • the new client process has been found and 8 s have passed since its StartTime (Roblox has read the XML by then)
    • a 30 s timeout
    • any exception
    Use try/finally so a failed launch never leaves the gate held.
  • Main snapshot: file FastFlags\Main.settings.json holds a subset of XML properties: SavedQualityLevel, GraphicsQualityLevel, FramerateCap, MasterVolume, plus any other keys the user lists in the file.
    • CaptureMainSnapshot(): read those properties from the XML and save them. Values come from <Properties><token|int|float|bool name="X">; reuse the existing ApplyGlobalBasicSettings lookup logic in reverse.
    • Capture manually with a button (Phase 6).
    • Capture automatically when RAM sees the main's RobloxPlayerBeta process exit: wait 2 s, then capture. Skip the capture if the captured values equal the alt profile's _RobloxSettings values, because that means an alt wrote last.
    • If no snapshot exists yet, create one from the XML the first time RAM is about to apply alt settings.
  • Per launch:
    • Main → write the snapshot into the XML (if one exists).
    • Alt → write the profile's _RobloxSettings into the XML. After the gate's settle point, write the main snapshot back.
    • This replaces the backup/restore of the XML for the main. Keep the existing .backup.json mechanism for ClientAppSettings.json in the fallback path only.
  • Keep RestoreOriginals() on startup and on close (already wired in AccountManager.cs). Also have it write the main snapshot back to the XML.

Acceptance: launch alt, then main, then close the alt, then relaunch the main. The main still opens with its own graphics level, FPS cap and volume.

Phase 5: Make alts cheaper (OS level, optional per setting)

Do this in RobloxWatcher.CheckProcesses, only for processes matched to an Alt account, and only once per process (track handled PIDs in a HashSet<int>):

  • AltEfficiencyMode (default on when UseAltClient is on):
    • process.PriorityClass = ProcessPriorityClass.BelowNormal.
    • Enable EcoQoS with SetProcessInformation(handle, ProcessPowerThrottling, ref PROCESS_POWER_THROTTLING_STATE { Version = 1, ControlMask = 1, StateMask = 1 }, size) (P/Invoke, Windows 10 1709+). Wrap it in try/catch and log failures once.
  • AltWindowWidth / AltWindowHeight (default 0 = off, suggested 800x600): in AdjustWindowPosition, when the account is Alt and has no remembered position, MoveWindow to that size. A smaller window renders far fewer pixels.
  • The existing TrimAltsMemory now uses the role helper from Phase 1.
  • Never touch the focused window's process priority. The watcher already skips focused windows; keep that.

Known unknowns (verify, don't assume)
  1. Direct-launch argument format. See the mandatory verification in Phase 3. If Roblox refuses the direct launch (error dialog, or it re-launches the installer), stop and report. Keep the fallback path as the default for alts until it's resolved.
  2. Whether Roblox writes GlobalBasicSettings on exit or only on setting change. Phase 4 is safe either way. Note the observed behavior in the final report.
  3. Allowlisted flags. Don't add flags to LowGraphicsPreset unless they're on the current Roblox allowlist. If unsure, leave the preset as is.
  4. Whether FramerateCap accepts values below 30. Test 15 and 20. If they're ignored, keep 30 and rely on EcoQoS.
