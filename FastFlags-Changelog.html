Bloxstrap x RAM: Low Graphics Alts

Changelog and setup guide for running many Roblox alts at the lowest possible graphics settings.

Changelog

Dedicated alt client

  • Main is an explicit group (configurable in Client Profiles). Main and numbered Main groups never receive profiles, even Default.json.
  • Dedicated alts run from AltClient\<version-guid>, with hard-linked game files and independent ClientSettings and AppSettings.xml. Your Bloxstrap flags remain untouched on this path.
  • Launch the main through RAM once per session to verify URI or supported switch arguments. Until verified, or if an installed version is missing, alts use the shared merge and restore fallback.
  • FastFlags\Main.settings.json preserves your main's graphics, FPS and volume. The launch gate waits for the new client to read settings, then restores the snapshot.
  • Client Profiles adds cleanup with backup and confirmation, manual main capture, version and role status, optional window size, and optional BelowNormal priority / EcoQoS for background alts.
  • The low graphics preset remains unchanged, including its 30 FPS cap. Values below 30 require in-game verification.

The following older entries describe the shared fallback. XML now uses the main snapshot rather than temporary XML backups.

Important: Roblox FastFlag allowlist

Since September 2025, Roblox only applies FastFlags that are on its official allowlist. Any other flag in ClientAppSettings.json is silently ignored. Bloxstrap writes to the same file, so it cannot get around this.

Source: Roblox DevForum: Allowlist for local client configuration via Fast Flags

As a result:

  • DFIntTaskSchedulerTargetFps (the FPS cap flag) no longer works. RAM's "Unlock FPS" setting no longer has an effect.
  • FFlagDisablePostFx, FIntRenderShadowIntensity and FIntRenderLocalLightUpdatesMax/Min no longer work.
  • DFIntTextureQualityOverride only works if DFFlagTextureQualityOverrideEnabled is also set to True.

To make up for this, RAM now also lowers Roblox's own in-game settings (graphics quality, FPS cap, volume) for alts.

Bloxstrap detection

  • RAM checks which program opens roblox-player: links.
  • If it is Bloxstrap (or a fork with a Modifications folder, such as Fishstrap or Voidstrap), RAM writes FastFlags only to Bloxstrap\Modifications\ClientSettings\ClientAppSettings.json. Bloxstrap copies this folder into Roblox every time it launches.
  • Otherwise RAM writes to the Roblox version folders, as before.

Merge instead of replace

  • Before, RAM overwrote your whole ClientAppSettings.json with the group's file, so your own flags were lost.
  • Now RAM keeps your flags and adds the group's flags on top. When both set the same flag, the group's value wins.

Automatic backup and restore

  • The first time an alt profile is applied, RAM saves your original ClientAppSettings.json to FastFlags\.backup.json.
  • Your originals are restored:
    • at the launch gate settle point (with a 15 second launcher notification timer as a backup),
    • immediately when an account with no matching group file launches (your main),
    • when RAM closes,
    • at the next RAM startup, if RAM crashed while a profile was applied.
  • If a restore fails, the backup is kept so the next restore can try again.

In-game settings (_RobloxSettings)

  • A group JSON file can contain a "_RobloxSettings" object.
  • Its values are written into %LocalAppData%\Roblox\GlobalBasicSettings_13.xml, which holds Roblox's in-game settings.
  • RAM removes this object before writing the FastFlags, so Roblox never sees it as a flag.
  • Only settings that already exist in the file are changed. Unknown names are skipped and logged.

Low graphics preset button

  • New button in Settings, Miscellaneous tab: "Create Low Gfx Preset".
  • It writes FastFlags\Alts.json, asks before overwriting an existing one, and turns on Group-Based FastFlags.
  • The preset uses only allowlisted flags.

Files changed

  • RBX Alt Manager/Classes/ClientSettingsPatcher.cs (rewritten)
  • RBX Alt Manager/Classes/Account.cs (restore timer starts after launch)
  • RBX Alt Manager/AccountManager.cs (restore on startup and on close)
  • RBX Alt Manager/Forms/SettingsForm.cs and SettingsForm.Designer.cs (preset button)
  • FastFlags/README.txt (updated guide)

Setup Tutorial

  1. Close all Roblox clients. Open Settings > Miscellaneous > Client Profiles and click Clean Bloxstrap flags. Review the removed keys and keep the backup.
  2. Put your main account in group Main (or set a different Main group in Client Profiles).
  3. Put your alt accounts in group Alts. Number prefixes such as 01 Alts also work.
  4. Click Create Low Gfx Preset in Miscellaneous. It writes Alts.json and enables Group-Based FastFlags. Enable the dedicated alt client in Client Profiles.
  5. Launch the main through RAM, set your desired graphics, FPS cap and volume, then close it. Click Capture main's in-game settings now. Launching the main also verifies its argument format for this RAM session.
  6. Enable Multi Roblox. Launch one alt, then three, then the main alongside them.

Refresh Client Profiles status. Dedicated alts should run from AltClient; the main should run from your protocol handler's client folder. If arguments remain unverified, keep protocol fallback and check the log before relying on dedicated launches.

With Default.json present, the main still gets no profile. Closing an alt and relaunching the main should retain the captured main settings. Test AsyncJoin too; the launch gate serializes shared settings writes.

After Bloxstrap cleanup, record a hash of its ClientAppSettings.json before and after dedicated launches; it should be unchanged. Use Get-Process RobloxPlayerBeta | Select-Object Id,Path,PriorityClass to inspect client paths and background alt priority. Use fsutil hardlink list "AltClient\<guid>\RobloxPlayerBeta.exe" to verify hard links.

  "DFIntCSGLevelOfDetailSwitchingDistanceL34": "0",
  "DFFlagDebugPauseVoxelizer": "True",
  "FFlagDebugSkyGray": "True",
  "DFFlagDisableDPIScale": "True",

SettingWhat it does
DFFlagTextureQualityOverrideEnabled + DFIntTextureQualityOverrideForces the lowest texture quality.
DFIntDebugFRMQualityLevelOverrideForces render quality level 1.
FIntDebugForceMSAASamplesTurns off anti-aliasing.
FIntFRMMinGrassDistance / FIntFRMMaxGrassDistanceRemoves grass.
FIntGrassMovementReducedMotionFactorStops grass movement.
DFIntCSGLevelOfDetailSwitchingDistance (and L12, L23, L34)Switches meshes to low detail as soon as possible.
DFFlagDebugPauseVoxelizerStops lighting voxel updates, which saves CPU.
FFlagDebugSkyGrayReplaces the skybox with plain gray.
DFFlagDisableDPIScaleStops scaling up the render on high-DPI screens.
_RobloxSettings: SavedQualityLevel, GraphicsQualityLevelSets the in-game graphics slider to 1.
_RobloxSettings: FramerateCapSets the in-game maximum frame rate.
_RobloxSettings: MasterVolumeMutes the alt.

Capacity Estimates

These are estimates, not measurements. Actual numbers depend heavily on the game.

Test machine

  • CPU: AMD Ryzen 9 8940HX (16 cores / 32 threads)
  • RAM: 31 GB, with about 44 GB total memory limit (RAM plus page file)
  • GPU: NVIDIA GeForce RTX 5060 Laptop GPU (8 GB VRAM), plus AMD Radeon 610M integrated (512 MB)

When this was checked, 39.8 GB of the 44.3 GB memory limit was in use, because image generation and several browsers were running (Brave alone used 12.5 GB). Only about 4.5 GB was left, which is enough for roughly 4 to 8 alts. The estimates below assume those apps are closed.

Realistic targets

  • With heavy apps open: about 5 alts.
  • With browsers closed: about 20 to 25 alts in a light AFK-style game, or 10 to 15 in a heavy one.
  • With a larger page file as well (for example 32 GB): 30 or more in a light game. At that point CPU heat on the laptop becomes the limit.

About the memory trimmer

Auto Trim Alt Memory reduces how much RAM each alt actively uses, which makes Task Manager numbers look lower. It does not free the memory Windows has reserved for each alt; that memory moves to the page file instead. So the trimmer reduces slowdown, but it does not raise the number of alts you can launch. A larger page file does.

How to run more alts

  1. Close browsers, image generation and other heavy apps. This frees more memory than anything else.
  2. Enlarge the page file: System, Advanced system settings, Performance, Virtual memory.
  3. In Windows Settings, Display, Graphics, set RobloxPlayerBeta.exe to the RTX 5060. Otherwise some alts may run on the Radeon 610M, which has only 512 MB.
  4. Keep the laptop plugged in and in performance mode.
  5. Launch in batches using RAM's join delay (default 8 seconds) so startup spikes don't stack.

How to measure real numbers

  1. Close heavy apps.
  2. Launch 5 alts in the game you plan to use.
  3. Wait 2 minutes.
  4. In Task Manager, Details tab, read memory and CPU for each RobloxPlayerBeta.exe.
  5. Divide your free memory by the average memory per alt to get your memory limit.

Known Limitations

  • Closing an alt can undo the restore. Roblox saves its in-game settings when it closes, so an alt closing after the restore writes its low settings back. Launching your main through RAM fixes this. Launching your main outside RAM does not.
  • The 30 FPS cap is untested. Roblox may not accept every FramerateCap value. If alts don't cap at 30, change it to 60 in Alts.json.
  • The allowlist can change. Roblox can add or remove allowed flags at any time. If a flag stops working, check the DevForum post linked above.
  • Bloxstrap flag edits during a launch can be lost. If you change flags in Bloxstrap during the shared fallback while an alt profile is applied, the restore overwrites them with the backup.
  • "Old join" mode is not supported. The existing UseOldJoin branch never starts its prepared process; it remains unchanged.

Troubleshooting

  • Check RAM's log for lines starting with [FastFlags]. They show which file was applied, where it was written, and when originals were restored.
  • If your main launches with low graphics, close RAM (this restores your originals) and check Step 1 again.
  • If FastFlags\.backup.json exists while no alts are launching, a restore failed. Restart RAM to retry.
